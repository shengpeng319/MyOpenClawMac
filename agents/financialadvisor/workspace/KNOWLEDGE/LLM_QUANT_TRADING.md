# LLM与量化交易

*Emily如何正确使用LLM做量化交易*

---

## 核心认知：为什么不能直接用LLM做交易决策

### 反身性问题

金融市场是一个**反身性的对抗性系统**：
- 你的交易行为本身会改变市场规律
- 规律一旦被发现就会消失
- 这与物理世界（自动驾驶）完全不同

```
自动驾驶: 2020年和2024年的道路遵守相同的物理定律 → 数据越多越好
量化交易: 你的订单推动价格 → 做市商调整报价 → 规律消失
```

### 预训练目标不匹配

- LLM训练目标：**预测下一个词**（语言的条件概率）
- 交易需要：**在风险调整后，最大化期望收益**

LLM会说"这份财报超预期，股价应该上涨"，但它无法准确告诉你"在当前宏观环境下，超预期财报触发向上跳空的概率密度分布是什么"。

### 提示词的蝴蝶效应

同样的市场信息，换一个提示词框架，结论可能完全相反：
```
"分析这只股票的走势" → 看涨
"评估这只股票的风险" → 看跌
```

### 置信度校准差

LLM经常给出很确定的答案，但实际准确率和置信度根本不匹配。

## 正确用法：LLM做信息提取层

### 正确框架
```
原始非结构化数据（财报PDF、新闻、央行声明）
        ↓  LLM（信息提取、分类、情感打分）
结构化特征（超预期幅度、政策倾向、业务扩张信号）
        ↓  传统量化模型（线性模型、随机森林、小型神经网络）
交易信号
        ↓  风险管理系统（仓位限制、相关性控制）
最终头寸
```

Two Sigma就是这么做的。

| 信号类型 | 例子 | LLM处理方式 |
|----------|------|-------------|

## 元策略生成：Emily的独特价值

LLM的顶级用法**不是选择现有策略，而是自动化研发新策略**：

```
人类交易员想法："最近跨期价差和库存数据关联变强了"

Emily执行流程：
1. 调取最近3个月的跨期价差数据 + 库存报告
2. 验证相关性是否确实结构性变化（而非偶然）
3. 生成Python代码：基于库存预测模型的跨期套利策略
4. 自动回测2019-2026年表现
5. 输出报告：夏普比率1.8，最大回撤8%，建议小资金试运行
6. 生成监控Dashboard代码，跟踪策略健康度
```

## 参数时变性的处理

### 核心问题

```
大模型假设：P(收益 | 信号) 是固定的，用更多数据估计它
正确的假设：P(收益 | 信号; θ_t) 中的 θ_t 是时变的，需要实时追踪
```

### 解决方案

| 方法 | 解决的问题 |
|------|----------|
| 卡尔曼滤波/贝叶斯在线学习 | 追踪θ*随时间的漂移 |
| HMM Regime Detection | 显式估计当前regime_t是什么 |
| 多模型集成+动态权重 | 用集成的方式隐式适应θ*的变化 |

**本质：把静态优化问题，转化成动态追踪问题。**

## 为什么顶级对冲基金不用大模型

### 原因一：容量矛盾
大模型运营成本高，需要部署大量资金 → 只能去容量大的信号 → 低频、被充分竞争、Alpha极低

### 原因二：Alpha半衰期
| 信号类型 | 半衰期 |
|---------|--------|
| 高频做市信号 | 数小时到数天 |
| 短期动量信号 | 2-6周 |
| 财报超预期效应 | 1-3个月 |
| 基本面因子 | 1-3年 |

大模型的训练周期是月到季度级别。等你训练完、部署好，很多短期信号可能已经过了半衰期。

### 原因三：参数本身是时变的
金融市场里，最优参数本身在随时间变化，不是因为被套利，而是因为市场结构在变。

## Emily的工作流程

### 1. 感知（Perception）
- 获取行情数据
- 读取新闻和政策文本
- 分析社交媒体情绪
- 历史类比检索

### 2. 理解（Understanding）
- 市场状态识别（Regime Detection）
- 非结构化信号结构化
- 跨市场因果链分析

### 3. 策略（Strategy）
- 因子加工与评分卡
- 多策略动态调度
- 新策略探索

### 4. 风控（Risk Control）
- 层级风控体系
- 情境化止损判断
- 相关性监控

### 5. 执行（Execution）
- Broker对接
- 订单分批执行
- 交易记录

### 6. 复盘（Review）
- 归因分析
- 策略健康度评估
- 参数漂移检测
- 进化优化
