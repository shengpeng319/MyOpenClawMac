## 今日重要发现

### 1. 飞书语音 Transcript 真相（重要澄清）

**之前的说法是错的**。经过反复核实：

- 飞书语音消息的 **API payload 只有 `file_key` + `duration`**，没有内嵌 transcript
- 日志里看到的 `Transcript:` 是 OpenClaw **自己尝试转录的结果**，但**全部失败**
- 用户在飞书 App 里看到的 Transcript 是**飞书客户端本地渲染**的，不通过 API 传递
- **结论**：OpenClaw 本身的 STT 没有配置，无法处理语音

### 2. 飞书发送音频的正确方式（已验证）

**上传**：`POST /im/v1/files` → `file_type=opus`
**发送**：`POST /im/v1/messages` → `msg_type=audio`，content 为 `{"file_key":"..."}`

注意：MP3/音频文件上传时必须用 `opus` 类型，不是 `audio` 不是 `mp3`

### 3. MiniMax music-2.6 模型已配置

- 调用方式：直接 POST 到 MiniMax API（不是通过 OpenClaw 对话模型）
- 生成示例：`/tmp/test_music.mp3`（舒缓女声轻音乐，807KB）
- API endpoint: `https://api.minimaxi.com/v1/music_generation`
